# Flickey

웹캠 손동작으로 슬라이드와 마우스를 제어하는 macOS용 발표 앱입니다. React·TypeScript·Vite·Electron과 로컬 MediaPipe 모델을 사용합니다.

## 네 페이지

| 페이지 | 경로 | 기능 |
| --- | --- | --- |
| 홈 | `#/home` | 발표 프로필, 발표 링크, 자료 추가·실행, 카메라 ON/OFF, 발표 시작·종료 |
| 설정 | `#/settings` | macOS 권한, 기본 모션의 커스텀키, 포인터 감도 |
| 가이드 | `#/guide` | 준비 순서, 손동작, 기능 설명, 화면 공유 안내 |
| 개발 | `#/developer` | 손 추적 오버레이 ON/OFF·위치·크기, 제어 모니터, 실행 로그 |

페이지를 이동해도 카메라와 발표 세션은 유지됩니다. 화면 컴포넌트는 `src/pages/`에 분리되어 있으며, 공통 상태와 명령 처리는 `src/features/presentation/usePresentationController.ts`에 있습니다.

## 홈 레이아웃

발표 제어 센터를 상단 중앙에 두고, 발표 시작·카메라 표시 방식·카메라 ON/OFF·슬라이드 이동·발표 복귀를 함께 배치했습니다. 아래의 **발표 준비**에서는 프로필과 자료를 한곳에서 관리합니다.

자료 목록에서 하나를 고르면 옆 편집기에 해당 자료만 표시됩니다. 새 자료는 추가 즉시 편집할 수 있으며 자료가 많아도 목록만 스크롤됩니다. 작은 화면에서는 프로필·자료 목록·편집기가 세로로 배치됩니다.

## 홈의 카메라 표시 방식

카메라가 꺼져 있어도 카메라 영역 위에서 **전체 화면 / 손만 보기**를 선택할 수 있습니다. 전체 화면은 카메라 영상과 손 추적을 함께 표시하고, 손만 보기는 영상만 숨긴 채 손 추적을 표시합니다. 전환할 때 카메라나 손 인식을 재시작하지 않으며 선택은 저장됩니다. 개발 페이지의 외부 오버레이 ON/OFF와는 별도 설정입니다.

## 통합 포인터

기존 CURSOR와 LASER 모드를 통합했습니다. 실제 시스템 커서의 이동·클릭과 레이저 표시가 같은 보정 좌표를 사용합니다. 홈에는 모드 선택 버튼이나 레이저 설정 칸이 없습니다.

- 슬라이드 모드: 한 손의 검지·중지·약지 펼치기 또는 양손 펼치기
- 포인터 모드: 한 손 L 모양. 기존 검지 X·뿔 모양·양손 V 사인도 포인터로 연결
- 모드 전환 유지시간: 약 0.7초
- 이동: 오른손 검지 또는 붙인 검지·중지
- 클릭: 왼손을 펼친 후 주먹 쥐기
- 모션 ON/OFF: 전화 모양 약 1.2초
- 긴급 정지: 양손 주먹 약 0.9초

## 오버레이와 인식의 분리

카메라와 손동작 인식은 메인 렌더러 한 곳에서 실행합니다. 오버레이 창은 전달받은 손 좌표를 그리기만 하며 카메라나 발표 명령을 직접 실행하지 않습니다.

개발 페이지에서 오버레이를 끄면 표시만 사라집니다. 카메라·인식·모션 상태는 바뀌지 않습니다. 홈에서 카메라를 끄면 영상 트랙과 모션 제어를 정지하고 남아 있는 손 그림도 지웁니다.

## 기본 모션과 커스텀키

| 기능 | 손동작 | 기본 키 |
| --- | --- | --- |
| 다음 슬라이드 | 손바닥 오른쪽 스와이프 | → |
| 이전 슬라이드 | 손바닥 왼쪽 스와이프 | ← |
| 화면 가리기 | 손바닥 약 0.8초 | B |
| 발표 종료 | 주먹 약 1초 | Escape |

설정에서 **키 지정 버튼을 누른 후 키 조합을 입력**합니다. Command·Control·Option·Shift 조합을 지원합니다. Tab은 포커스 이동용으로 남겨 두었습니다. 기존 손동작 종류는 바뀌지 않으며, 선택한 키는 프로필에 자동 저장됩니다. 복원 버튼으로 해당 동작의 기본키로 돌아갑니다.

- 자료 선택: V 사인 약 0.7초
- 선택 자료 실행: 검지 하나 약 0.7초
- 자료 유형: 웹 링크, 로컬 파일, 애플리케이션
- 기존 자료 테스트, 삭제, 5초 후 발표 복귀, 특정 슬라이드 이동 지원

기존 프로필 저장 키 `flickey.presentation-profile.v1`을 유지합니다. 커스텀키가 없는 기존 프로필에는 빈 설정을 보완하고 자료와 발표 링크를 보존합니다.

## 실행

지원 해상도 1100×720 이상, 권장 1280×800. 더 작은 창에서는 화면이 겹치지 않고 스크롤됩니다.

macOS, Node.js, Xcode Command Line Tools가 필요합니다.

```sh
npm ci
npm run dev:electron
```

브라우저용 `npm run dev`는 UI 확인용입니다. 실제 발표 앱, 파일 선택, 시스템 커서와 오버레이는 Electron에서 작동합니다.

```sh
npm run test:electron   # 외부 패키지 설치 없이 실행하는 Electron 로직 회귀 검사
npm test               # UI·프로필·손동작 단위 검사
npm run lint
npm run build
```

## 배포

```sh
sh scripts/build-icon.sh
npm run dist:mac
```

네이티브 입력 코드가 변경되었으므로 기존 배포 앱에 UI만 덮어쓰지 말고 네이티브 모듈도 함께 다시 빌드해야 합니다. 기존 스크립트는 Apple Silicon용 앱·DMG·ZIP을 생성합니다.

## 실제 환경 확인

손쉬운 사용 권한이 있어야 시스템 입력을 전달할 수 있습니다. 카메라 권한도 필요합니다. 레이저·손 오버레이는 별도 창이므로 전체 화면 공유에서 확인하세요. 특정 창만 공유하는 경우 서비스의 마우스 포인터 전송 설정에 따라 표시가 달라집니다.

이번 작업의 검증 결과와 아직 확인하지 못한 항목은 [IMPLEMENTATION_REPORT.md](IMPLEMENTATION_REPORT.md)에 정리했습니다.

## 웹 제출용 리허설

웹에서 홈의 **웹 리허설 시작**을 누르면 자료 없이 카메라·모션을 켜고 샘플 슬라이드와 포인터를 시험할 수 있습니다. 카메라 없이도 샘플 버튼을 사용할 수 있습니다. 카메라는 HTTPS 또는 localhost가 필요합니다. 외부 발표 링크는 새 탭으로 열 수 있지만, 외부 사이트/OS 마우스 제어는 Electron 전용입니다. 이 리허설은 실제 업로드 자료를 조작하는 뷰어가 아닙니다.

Electron에서 권한을 변경한 뒤 앱으로 돌아오면 상태를 다시 조회합니다. 개발 실행 시 권한 목록에 Electron으로 표시될 수 있습니다. 앱 수정 후에는 Electron을 재시작하세요.


### 데모 발표 팝업

‘데모 덱으로 연습’ → ‘발표 시작’으로 5장의 데모를 별도 창에서 엽니다. 열린 발표 창은 재사용하며, 팝업 차단 시 사이트의 팝업 허용 방법을 안내합니다. PDF 발표는 지원하지 않습니다.

- 이전·다음 버튼, 방향키, Home/End로 이동합니다. 이동하면 검은 화면이 해제됩니다.
- 전체 화면은 브라우저 Fullscreen API를 사용합니다. 하단 조작 영역에 마우스를 올리거나 Tab으로 포커스를 옮기면 버튼이 나타납니다.
- 팝업의 ‘모션 시작’으로 카메라와 기존 손 인식을 실행합니다. 홈의 카메라는 발표 창을 열 때 정지합니다.
- 데모의 슬라이드·검은 화면·포인터·클릭은 팝업 내부에서 처리하며 외부 발표 앱과 OS 커서를 제어하지 않습니다.
- 스와이프 후 유지하는 손바닥은 검은 화면을 실행하지 않습니다. 손을 내리거나 자세를 바꾼 뒤 다시 손바닥을 유지하세요.
- ‘모션 정지’, ‘카메라 끄기’, 양손 주먹 긴급 정지를 지원합니다. 카메라 영상·손 추적 캔버스·진단 패널은 발표 화면에 표시하지 않습니다.

검증: Vitest 25개, Electron 회귀 테스트 10개, lint와 프로덕션 빌드 통과. 카메라·인식 콜백·Fullscreen API는 자동 테스트에서 모의 실행했으며, 실제 카메라의 인식 정확도와 실제 브라우저 전체 화면 표시는 별도 수동 검증이 필요합니다.
